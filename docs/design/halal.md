# Halal

A household that eats halal gets only halal dishes, and its meat comes only from products certified halal (Knowledge
ADR-0104, owner 2026-10-29; it supersedes ADR-0091's "not supported yet"). Unknown is never halal (ADR-0068,
ADR-0073 section 5, ADR-0076 section 2).

## Where it comes from

- **Household:** the household profile has one switch, `requires_halal` (default `false`), on the whole household.
  Under the shared-dish model one halal member makes the shared table halal, so there is no per-member switch.
- **Chat:** a clear request ("halal", "清真") sets `requires_halal` for that plan, with the existing negation
  handling ("no need for halal", "不需要清真"). The reply offers to save it to the profile; it is saved only on a
  yes. The flag is stored with the plan's constraints, so swaps, can't-buy replans and shape changes keep it.
- **Interfaces:** every HTTP interface that accepts a halal flag keeps it as a required field (ADR-0091 item 2,
  restated in ADR-0104). Where the flag comes from the profile, the server derives it.

## Ingredient labels: `data/ingredients/halal-labels-v1.json`

One entry per catalog ingredient (the release v2.2 ingredients plus the curated ones):

```json
{"normalized_name": "chicken_breast", "status": "halal", "needs_certification": true,
 "source": "rule:meat", "reason": "poultry: halal only from a certified product"}
```

- `status` is `halal`, `not_halal` or `uncertain`. `uncertain` counts as not halal everywhere.
- `needs_certification` is `true` for meat and poultry and for products made from them whose slaughter is not
  stated (beef broth, meatballs). It is never `true` on a `not_halal` entry. Sausage is `uncertain`, not
  `needs_certification`: the hierarchy says it may contain pork.
- `source` names the rule that decided it, so a reviewer can audit by rule:
  - `rule:pork`: the pork family of the ingredient hierarchy, including lard, bacon, ham, gelatin of pork;
  - `rule:alcohol`: `group:alcohol` of the hierarchy, including cooking wine and mirin;
  - `rule:may_contain`: a hierarchy `may_contain` link to pork or alcohol, which makes the item `uncertain`;
  - `rule:doubtful`: gelatin of unstated source, emulsifiers, stock cubes or powder of unstated source,
    alcohol-based extracts;
  - `rule:meat`: halal with `needs_certification`; also an item with a `may_contain` link to meat (ramen,
    stuffing mix: flavour packets), checked after the pork, alcohol, doubtful and `may_contain` rules above;
  - `rule:food_group`: plant foods, fish and seafood, eggs, dairy, grains, legumes, nuts, seeds, fruit,
    vegetables are halal;
  - `human`: confirmed or corrected by a person.
- The file is generated by `python -m app.data.halal_labels` from the hierarchy, the release food groups and the
  lists in that module, and then reviewed. It is deterministic; a person's correction is kept in
  `data/ingredients/halal-overrides-v1.json` and applied last.
- Review queue: the generator also writes `data/ingredients/halal-review-v1.csv`. It lists every `uncertain`
  entry, every `needs_certification` entry and a fixed-seed sample of 60 `halal` entries, each with a blank
  verdict for a person. AI suggestions may be added to the queue, but take effect only after a person confirms them
  (ADR-0076 section 2).

## Code interface: `backend/app/data/halal.py`

- `halal_labels() -> dict[str, HalalLabel]` reads the labels with the overrides applied.
- `recipe_halal_status(ingredient_names) -> str` applies the table below.
- `needs_certification(name) -> bool`.
- `release_halal_certification() -> dict[str, bool | None]` reads the offline product facts.
- `product_certified(product_id) -> bool | None` looks one up by a frozen or fixture id (`fixture:` and the
  `@ingredient` suffix of a product shared by two ingredients are dropped).

The labels and the facts are cached. The planner, the import and the evaluation call only these.

## Recipe status

Derived from the recipe's ingredient lines, at import and for curated recipes, into `recipes.halal_status`, and
for ingredients into `ingredients.halal_status`:

| The recipe's lines | `halal_status` |
|---|---|
| any `not_halal` | `not_halal` |
| else any `uncertain`, or an ingredient with no label | `uncertain` |
| else any `needs_certification` | `needs_certification` |
| else | `halal` |

- An at-home item (ADR-0107) is still a line of the recipe, so mirin at home still makes a recipe not halal.
- ADR-0104 item 5 allows a halal composite substitute for an alcohol ingredient (for example for mirin). This
  version does not build it, so such a recipe stays `not_halal`.

## Certified products

- `ProductResponse.halal_certified: bool | None`. The FairPrice parser sets `true` when the listing record's
  `metaData["Dietary Attributes"]` contains `"Halal"`, and `None` otherwise. A missing attribute is unknown, never
  `false`, and never inferred from a name. `product_snapshots.halal_certified` stores it.
- **Offline facts.** The products of the release price snapshot carry no attribute. A one-off capture,
  `python -m app.data.capture_fairprice_halal`, reads FairPrice's public listing for the snapshot's products of
  `needs_certification` ingredients. It writes `data/ingredients/fairprice-halal-v1.json`
  (`{external_id: {"halal_certified": true | null, "observed_at": ...}}`). Snapshot and fixture pricing read it, and
  live pricing uses the live attribute.
- Cold Storage products have no verified attribute, so they are never chosen for a `needs_certification` line.

## Planning

- **Eligibility.** One helper, `halal_ok(recipe, problem)`, used by the compiler, the meal beam, the reference
  planner, the validator and the recommendation engine. With `requires_halal` it accepts:
  - a recipe whose status is `halal`;
  - a recipe whose status is `needs_certification`, when every `needs_certification` line has at least one
    certified product option in the problem.

  Everything else is rejected.
- **Product choice.** With `requires_halal`, a `needs_certification` line's product options are only certified
  products, in the planner's options and in `grocery_estimator.choose_product`. The shopping list and the
  FairPrice cart therefore buy that product, never a cheaper uncertified one.
- **Validation.** The independent validator re-checks both rules on the final plan: every dish passes `halal_ok`,
  and every `needs_certification` line's chosen product is certified.

## Evaluation

- The ingredient-level baseline scorer maps a baseline's dish lines to catalog ingredients and applies the same
  labels. An unmapped or `uncertain` line fails a halal case.
- Developer cases include halal households: pork-free but uncertified meat, unknown-status ingredients, and a
  5-person halal week.
- The halal pool is reported: recipes by status, and how many are plannable for a halal household.

## Not in this version

- MUIS certification list (ADR-0104 item 4).
- Halal composite substitutes for alcohol ingredients.
- Per-member halal.
