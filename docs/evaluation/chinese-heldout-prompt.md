1. **每一条都用中文写**（简体；新加坡、马来西亚华人家庭常用的叫法也算中文）。
2. 任务 A 的 `kind` 一律写 `chinese`（目录里没有的写 `none`）；一半左右写**一两个字的短词**，其余写两三个字的

3. 任务 B 的每句话都用中文说，覆盖面同上一套（蛋白质、主食、菜系、口味、饮食）。

## 任务 A：家里人会怎么说一个食材（约 40 条）

系统遇到它不认识的食材说法时，会给出几个目录里的食材让用户挑。这套题检查「正确的那个有没有在候选里」。

每条题写：

- `term`：用户真的会打的那个词。（本套只写中文。）
- `context`：一句完整的话，说明这个词是怎么出现的。
- `accept`：目录里**哪些食材 id 算说对了**，从包里 data 文件夹的 `catalog-ingredients.csv` 里查。可能不止一个
  （一个说法可能对应两种相近的食材）。目录里确实没有的，写空列表 `[]`。
- `kind`：这个词属于哪一类，从下面选：
  `synonym`、`british`、`american`、`regional`、`chinese`、`malay`、`spelling`、`typo`、`short`、`none`、`other`。
  `accept` 为空时必须写 `none`。

要求：

- **写真实会出现的词，不要写刁钻的陷阱。** 先想一个真实的家庭场景，再想他们会怎么称呼这个食材。
- **直接照抄目录名称的不能超过 10%。** 「chicken breast」对 `chicken_breast` 什么也测不出来。
- 覆盖面要广：肉、海鲜、蔬菜、调料、主食都要有；中文、本地叫法、英式叫法、拼错都要有；
  其中 3 到 5 条是目录里没有的（`none`）。
- 判断 `accept` 时想清楚「同一样东西」：花生油不是花生，鱼露不是鱼。拿不准就查资料，不要猜。

## 任务 B：换菜时会怎么说（约 20 句）

用户会说「周三换成别的」，有时还会说想吃什么。这套题检查：系统换上来的菜，是不是用户想要的那种。

每条题写：

- `request`：用户真的会说的那句话，**必须带一个具体的要求**。
  只说「换一个」的不要。
- `check`：用目录里的事实怎么判断「换对了」。从下面五种里选一种，`values` 从 data 文件夹的 `catalog-facts.md`
  和 `catalog-ingredients.csv` 里查：
  - `any_ingredient`：菜里有这些食材中的任意一个
  - `cuisine`：菜系是这些之一（例：`japanese`）
  - `dietary_tag`：带这些饮食标签之一（例：`vegetarian`）
  - `title_word`：菜名里出现这些词之一（例：`curry`）
  - `course`：菜的类别（主菜题里一般用不上）
- `note`：一句话说明为什么这样判断算合理。

要求：

- **先写一句真实的话，再想怎么判断。** 不要为了好判断去编话。
- 判断必须和那句话一致：说「想吃鱼」就不能用 `cuisine: japanese` 来判断。
- 校验脚本会算出每个判断在所有主菜里的覆盖率，必须在 1% 到 60% 之间：太少的话抽样时根本抽不到，
  太多的话随便选都对。不在范围内就换一个说法或放宽、收紧判断。
- 覆盖面要广：蛋白质（鱼、牛、鸡、豆腐、虾……）、主食（面、饭、意面）、菜系、口味（辣、清淡）、
  饮食（素食）；中文和英文都要有。
