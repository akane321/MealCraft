## 结果与限制

15组均生成计划且家庭检查通过。五个家庭中四个的不同菜数、最大重复和购物总价在三档保持一致。六人家庭在200步时，产品整桌菜类从48增加到50，购物总价从S$266.09增加到S$410.50（增加S$144.41），未超过S$420预算；按recipe ID计算的56道不同菜没有变化。两个统计口径不能混用。

这是当前“多样性优先、价格靠后”的排序产生的取舍，不是最低价改善证据。不据此将默认步数从50提高到200，也不擅自增加“价格不得上升”的新规则。

200步组的总耗时明显较长，但不能全部归因于退火：六人家庭的候选生成调用次数在50步和200步都是84次，测量耗时却从约65秒变为310秒；退火提案计时约从0.46秒变为8.81秒。运行环境可能影响结果，单次顺序测量不能判断因果。后续应交错顺序重复测量，区分环境变化和算法开销。

## 剩余工作

- 本轮只扫描步数，未完成复合家庭的宽度与步数组合校准。
- 当前输出的菜数是recipe ID统计，优化目标是整桌dish_kind，不能声称成员平均多样性或独立近似菜准确率达标。
- 价格来自fixture；真实价格快照、全目录最低价5%证据和混合包装接入仍未完成。
- 跨周衰减需要历史输入与检查、保存的一致性；本轮未实现。
- PAIR-030仍为拿不准，原始答卷未修改。正式近似阈值和全目录换菜验收仍需后续证据。

复现：`python scripts/product_household_comparison.py --output <fresh-directory> --steps 0 50 200 --profile`。三份JSON记录源码提交、脚本哈希、机器信息、完整检查与各阶段耗时。未修改产品默认参数，未合并PR。
